# DoMap

Мобильное приложение на React Native и Expo: карта, на которой можно ставить метки мест и
прикреплять к каждому месту фотографии. Все данные хранятся в локальной базе SQLite на телефоне.

Выполнено в рамках практических заданий «Приложение на React Native с картой» (задание 1),
«Приложение с картой и локальной базой данных» (задание 2) и «Приложение с картой, геолокацией
и уведомлениями» (задание 3).

## Возможности

- Карта на весь экран; положение пользователя обновляется в реальном времени, пока приложение открыто.
- Уведомление «Вы рядом с меткой!», когда пользователь оказывается ближе 100 м к сохранённому месту.
- Метки в виде сердечек: закрашенных у мест с фотографиями и контурных у пустых.
- Долгое нажатие по карте создаёт новое место: приложение спрашивает название и открывает его экран.
- Нажатие на метку открывает «облачко», а нажатие на «облачко» — экран деталей места.
- Экран места: название, координаты, дата добавления, галерея фотографий.
- Переименование места в любой момент.
- Добавление фотографий из галереи телефона и удаление по одной.
- Просмотр фотографии на весь экран по нажатию.
- Отдельная вкладка «Места» со списком всех меток и превью последней фотографии.
- Удаление места вместе с его фотографиями.
- Данные лежат в базе SQLite на телефоне и остаются после перезапуска приложения.

## Установка и запуск

Нужны Node.js (LTS) и приложение Expo Go на телефоне. Сервер базы данных не нужен: SQLite —
это файл `markers.db` внутри приложения, он создаётся сам при первом запуске.

```bash
npm install
npx expo start
```

Дальше отсканируйте QR-код камерой (iOS) или приложением Expo Go (Android).
`expo-sqlite`, `expo-location` и локальные уведомления `expo-notifications` входят в Expo Go,
отдельная сборка приложения не требуется.

Проверка кода:

```bash
npx tsc --noEmit   # типы
npx expo-doctor    # совместимость версий пакетов
```

## База данных

### Схема

```sql
CREATE TABLE markers (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  title TEXT NOT NULL,
  latitude REAL NOT NULL CHECK (latitude BETWEEN -90 AND 90),
  longitude REAL NOT NULL CHECK (longitude BETWEEN -180 AND 180),
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE marker_images (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  marker_id INTEGER NOT NULL,
  uri TEXT NOT NULL CHECK (length(uri) > 0),
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (marker_id) REFERENCES markers (id) ON DELETE CASCADE
);

CREATE INDEX idx_marker_images_marker_id ON marker_images (marker_id);
```

| Таблица | Что хранит |
|---|---|
| `markers` | Место на карте: название, координаты, время создания (UTC). |
| `marker_images` | Фотография места: ссылка на маркер и путь к файлу в папке приложения. |

**Связь** — один-ко-многим: у маркера может быть сколько угодно фотографий, у фотографии ровно
один маркер. `ON DELETE CASCADE` удаляет фотографии вместе с маркером.

**Отличия от схемы в задании:**

- `title` — название места. Оно было в задании 1, и его можно менять на экране места.
- `CHECK` на координаты и путь к файлу — некорректные данные не попадут в базу даже при ошибке в коде.
- Индекс по `marker_id` — выборка фото места и подсчёт фото для списка не перебирают всю таблицу.

**Сами файлы фотографий в базе не хранятся.** Выбранное фото копируется в
`documentDirectory/marker-images/`, а в `marker_images.uri` записывается путь к копии. База остаётся
маленькой и быстрой, а картинки грузятся напрямую с диска.

### Настройки соединения

При каждом открытии базы (`database/schema.ts`):

- `PRAGMA journal_mode = WAL` — чтение не ждёт записи.
- `PRAGMA foreign_keys = ON` — SQLite по умолчанию **не проверяет** внешние ключи и не выполняет
  `ON DELETE CASCADE`. Настройка действует только на текущее соединение, поэтому включается каждый
  раз, а после включения проверяется: если она не включилась, открытие считается неудачным.

### Версии схемы и миграции

Номер версии хранится в самой базе — `PRAGMA user_version` (у новой базы он равен 0).
`database/migrations/index.ts` при запуске сравнивает его со списком миграций и выполняет
недостающие по порядку. Каждая миграция идёт в транзакции вместе с записью нового номера: если
она упадёт, база откатится и останется на прежней версии, а не «наполовину».

Если номер в базе больше, чем знает приложение (база от более новой версии), открытие
останавливается с понятной ошибкой: старый код не должен трогать незнакомую схему.

Новая версия схемы — это новый файл `002_....ts` и новая строка в массиве `MIGRATIONS`.

### Операции

`database/operations.ts` — чистые функции без React: получают соединение, выполняют SQL,
возвращают данные в формате `types.ts`. Все значения передаются параметрами `?`, строки в SQL
не склеиваются.

| Операция | Что делает |
|---|---|
| `insertMarker` | Создаёт маркер, возвращает его `id`. |
| `updateMarkerTitle` | Меняет название. |
| `deleteMarker` | В транзакции берёт пути файлов фото и удаляет маркер (фото удаляются каскадом). |
| `selectMarkers` | Все маркеры с количеством фото и последним фото для превью — одним запросом. |
| `insertImage` | Добавляет фото к маркеру. |
| `deleteImage` | В транзакции берёт путь файла и удаляет строку. |
| `selectMarkerImages` | Все фото одного маркера. |

### Контекст `DatabaseContext`

`contexts/DatabaseContext.tsx` — единственная точка доступа к базе. Экраны не видят SQL и получают
через `useDatabase()`:

```ts
interface DatabaseContextType {
  addMarker: (latitude: number, longitude: number, title?: string) => Promise<number>;
  deleteMarker: (id: number) => Promise<void>;
  getMarkers: () => Promise<MapMarker[]>;
  addImage: (markerId: number, uri: string) => Promise<void>;
  deleteImage: (id: number) => Promise<void>;
  getMarkerImages: (markerId: number) => Promise<MarkerImage[]>;
  renameMarker: (id: number, title: string) => Promise<void>;

  markers: MapMarker[]; // последний прочитанный список — для карты и вкладки «Места»
  revision: number;     // растёт после каждого изменения — экран места перечитывает фото

  isLoading: boolean;
  error: DatabaseError | null;
  retry: () => void;    // открыть базу заново после ошибки
}
```

- **Соединение.** Провайдер открывает базу при монтировании и закрывает (`closeAsync`) при
  размонтировании — после того, как доработают уже начатые операции. Если экран закрыли, пока
  база открывалась, только что открытое соединение сразу закрывается.
- **Очередь операций.** Все операции выполняются строго по одной. Так запрос с одного экрана не
  вклинится в транзакцию, начатую другим.
- **Список мест** перечитывается из базы после каждого изменения, поэтому карта, вкладка «Места»
  и экран места всегда показывают одно и то же.

### Транзакции

Операции, затрагивающие обе таблицы или «прочитать и удалить», выполняются в транзакции через
`withTransactionAsync`: ошибка внутри — всё откатывается.

`withExclusiveTransactionAsync` здесь не используется: по документации expo-sqlite в такую
транзакцию попадают только запросы через объект `txn`, а операции приложения обращаются к базе
напрямую. Защиту от посторонних запросов внутри транзакции даёт очередь операций в контексте.

## Геолокация и уведомления

### Настройка

Отдельной настройки не нужно: `expo-location` и `expo-notifications` входят в Expo Go.

При первом открытии карты приложение по очереди спрашивает доступ к местоположению и к
уведомлениям. В Expo Go разрешения выдаются самому Expo Go, поэтому в настройках телефона их
нужно искать у Expo Go. Тексты запросов и цвет уведомлений заданы в `app.json` (плагины
`expo-location` и `expo-notifications`); они действуют в отдельной сборке приложения, а в Expo Go
используются тексты Expo Go.

**Патч `expo-notifications` для Expo Go.** В версии 57.0.23 Android-часть модуля подписок на
топики (это push через FCM) загружает нативный модуль `ExpoTopicSubscriptionModule` прямо при
импорте пакета. В Expo Go такого модуля нет, и приложение падало при запуске с ошибкой
`Cannot find native module 'ExpoTopicSubscriptionModule'`. Патч
`patches/expo-notifications+57.0.23.patch` делает загрузку необязательной: в отдельной сборке модуль
работает как обычно, а в Expo Go подставляется пустая заглушка — такая же, как в самом пакете для
iOS. Патч применяется автоматически после `npm install` и `npm ci` (скрипт `postinstall` запускает
`patch-package`).

### Как устроено

| Файл | Что делает |
|---|---|
| `services/location.ts` | Проверяет службы геолокации, запрашивает разрешение и подписывается на `watchPositionAsync`: точность `Balanced`, обновления не чаще раза в 5 с (Android) и только при смещении хотя бы на 5 м. |
| `lib/geo.ts` | Расстояние между двумя точками в метрах по формуле Хаверсина. |
| `services/notifications.ts` | Обработчик показа, канал Android, разрешение на уведомления и `NotificationManager`. |
| `components/Map.tsx` | Запускает отслеживание при открытии карты и снимает подписку при уходе с экрана, показывает ошибки, при каждом новом положении и изменении списка мест вызывает проверку близости. |

### Стратегия управления уведомлениями

- **Вход в зону** — ближе 100 м к месту: одно уведомление «Вы рядом с меткой!» с названием места.
  Оно уходит сразу, без расписания. В отдельной сборке — в свой канал Android «Приближение к месту»
  с высокой важностью, чтобы всплывать поверх экрана. В Expo Go создать свой канал нельзя (вызов
  падает внутри самого Expo Go), поэтому там уведомление идёт в канал Expo Go по умолчанию.
- **Выход из зоны** — дальше 150 м: уведомление убирается из шторки (`dismissNotificationAsync`:
  оно уже показано, отменять расписание нечего). Между 100 и 150 м ничего не меняется — иначе на
  границе дрожание GPS показывало бы и убирало уведомление снова и снова.
- **Активные уведомления хранятся в памяти** — `Map<markerId, ActiveNotification>` в
  `NotificationManager`. Пока для места есть запись, второе уведомление не появится. Запись
  удаляется только при выходе из зоны, поэтому смахнутое уведомление не вернётся, пока пользователь
  не выйдет из зоны и не войдёт снова.
- **Очередь операций.** Проверки приходят из эффектов (новые координаты, изменился список мест) и
  могут наложиться. Все операции менеджера выполняются по одной: иначе две проверки одновременно
  увидели бы «уведомления ещё нет» и показали бы его дважды.
- **Перезапуск приложения.** Память очищается, а шторка — нет. При запуске (`initNotifications` в
  `app/_layout.tsx`) менеджер читает уже показанные уведомления (`getPresentedNotificationsAsync`)
  и по `markerId` в их данных восстанавливает список активных.
- **Удалённые места.** Если места больше нет в списке, его уведомление убирается при следующей проверке.
- **Без разрешения на уведомления** проверка близости не выполняется, карта при этом работает.

### Тестирование

1. **Быстрая проверка на месте.** Откройте карту, разрешите геолокацию и уведомления. Долгим
   нажатием поставьте место рядом со своей точкой — уведомление придёт сразу. Пока вы рядом,
   второго не будет. Удалите место — уведомление исчезнет из шторки.
2. **Несколько мест.** Поставьте два места рядом с собой — придёт по уведомлению на каждое.
3. **Выход и повторный вход.** Отойдите дальше 150 м — уведомление уберётся; вернитесь ближе
   100 м — придёт снова. Без прогулки то же проверяется подменой координат:
   - телефон на Android: «Настройки → О телефоне», семь раз нажать «Номер сборки», затем в разделе
     «Для разработчиков» выбрать «Приложение для фиктивных местоположений» (подойдёт любое
     приложение подмены GPS) и задавать точки в нём;
4. **Фоновый и активный режим.** Уведомление, пришедшее при открытом приложении, показывается
   баннером. Сверните приложение — отслеживание приостанавливается (см. ограничения), разверните —
   продолжается с новой точки.
5. **Перезапуск.** Находясь рядом с местом, закройте приложение и откройте снова — второго
   уведомления не будет.
6. **Перезагрузка телефона.** Android очищает шторку; если после запуска вы всё ещё рядом, придёт
   одно новое уведомление.
7. **Ошибки.** Выключите геолокацию, запретите доступ к местоположению или к уведомлениям — на
   карте появится плашка (см. «Обработка ошибок»).
8. **Точность GPS** меняется в `DEFAULT_LOCATION_CONFIG` (`services/location.ts`).

## Обработка ошибок

### Ошибки базы данных

Все ошибки SQLite превращаются в `DatabaseError` (`database/errors.ts`) с видом и текстом для
пользователя. Экраны не разбирают сообщения SQLite сами.

| Вид | Когда возникает | Что видит пользователь |
|---|---|---|
| `init` | База не открылась, не включились внешние ключи, упала миграция, база от более новой версии | Сообщение и кнопка «Повторить» на карте и во вкладке «Места» |
| `connection` | База не открыта или закрыта, `database is locked` | То же: сообщение и «Повторить» |
| `constraint` | Нарушен внешний ключ или `CHECK` | Alert: например, «Место уже удалено» при добавлении фото к удалённому месту |
| `transaction` | Сбой внутри транзакции — изменения откатились | Alert: «Не удалось сохранить изменения, они отменены» |

Ошибки открытия базы и потери соединения попадают в `error` контекста и видны на всех экранах.
Ошибки отдельных операций пробрасываются вызывающему экрану, и тот показывает `Alert`.

### Восстановление после ошибок

- **«Повторить»** заново открывает базу: старое соединение закрывается, запускаются миграции.
- **Откат транзакций** — ни миграция, ни удаление не оставят базу в промежуточном состоянии.
- **Файл и запись согласованы.** При добавлении фото сначала копируется файл, потом создаётся
  запись; если запись не удалась, копия удаляется. При удалении сначала удаляется запись, потом
  файл; если файл удалить не вышло, это только логируется — список на экране уже верный.
- **Чтение после записи.** Если запись прошла, а перечитать список не удалось, ошибка только
  логируется: пользователь не увидит ложное «не удалось сохранить».
- **Некорректный адрес.** `id` из адреса экрана проверяется на целое число; мусор или удалённое
  место — экран «Место не найдено» с кнопкой возврата.

### Логирование

В режиме разработки (`__DEV__`) каждая операция пишет в консоль Metro имя и время выполнения:

```
[db] open — 12 мс
[db] migration v1 — 8 мс
[db] addMarker — 3 мс
[db] addImage — ошибка (constraint) addImage: FOREIGN KEY constraint failed
```

### Ошибки интерфейса 

- **Выбор изображения.** Проверяется разрешение на доступ к галерее, весь процесс обёрнут в
  `try/catch`, при сбое показывается понятное сообщение. Отмена выбора ошибкой не считается.
- **Навигация.** Переходы обёрнуты в `try/catch`. Кнопка «назад» проверяет, есть ли куда
  возвращаться, и иначе уходит на карту.
- **Загрузка карты.** Пока карта не готова, показывается индикатор. Если за 10 секунд карта не
  сообщила о готовности, появляется сообщение и кнопка «Повторить», которая пересоздаёт карту.

### Ошибки геолокации и уведомлений

Ошибки геолокации описывает класс `LocationError` с видом ошибки, отказ в уведомлениях —
`NotificationPermissionError` с флагом `canAskAgain`. По ним экран карты выбирает, что предложить:

| Ситуация | Вид | Что видит пользователь |
|---|---|---|
| Геолокация выключена на телефоне | `services-disabled` | Плашка «Геолокация выключена…» и «Повторить» |
| Отказ в доступе к местоположению | `permission-denied` | Плашка и «Повторить» — запрос появится снова |
| Система больше не показывает запрос | `permission-blocked` | Плашка, «Настройки» и «Повторить» |
| Сбой службы геолокации во время отслеживания | `unavailable` | Плашка «Не удалось получить координаты…» и «Повторить» |
| Отказ в уведомлениях | `canAskAgain` | Карта работает, плашка-предупреждение и «Повторить» (или «Настройки», если запрос больше не появится); проверка близости не выполняется |

Ошибки показа и снятия отдельных уведомлений только логируются: из-за одного места не стоит
прерывать проверку остальных.

## Почему без ORM

Здесь используется чистый `expo-sqlite`:

- В схеме две таблицы и семь запросов — ORM добавил бы зависимость и шаг генерации кода,
  не упростив сами запросы.
- SQL виден целиком: легко проверить, что каскад, индекс и транзакции работают как задумано.
- Типы результата задаются явно (`getAllAsync<MarkerRow>`) и приводятся к типам приложения
  в одном месте — `operations.ts`.

`@types/sqlite3` из списка зависимостей задания не установлен: это типы для Node-пакета `sqlite3`,
который в приложении не используется. У `expo-sqlite` типы встроены.

## Принятые решения

**Фотографии копируются в папку приложения.** Выбор изображения возвращает файл во временной
папке, которую система может очистить в любой момент. `lib/storage.ts` копирует файл в
`documentDirectory/marker-images/`, а при удалении фото или места файлы удаляются тоже.

**Карта на Android собрана на MapLibre GL.** Для Android карта сделана на MapLibre GL внутри `WebView`.
Стиль и данные берутся у OpenFreeMap (карта OpenStreetMap), ключи и регистрация не нужны.
На iOS остаётся `react-native-maps` с картой Apple. Metro подключает `MapSurface.android.tsx` на Android
и `MapSurface.tsx` на iOS; оба файла реализуют один интерфейс из `map-surface.types.ts`.

**Экран карты лежит в `app/(tabs)/index.tsx`.** Скобки в имени `(tabs)` — группа маршрутов
Expo Router: она задаёт общий макет с вкладками, но не входит в адрес. Адрес карты — `/`.

## Дополнительно реализовано

- Версии схемы и миграции через `PRAGMA user_version`, каждая миграция в своей транзакции.
- Проверки `CHECK` и индекс по внешнему ключу.
- Очередь операций с базой и закрытие соединения при размонтировании.
- Логирование запросов с временем выполнения в режиме разработки.
- Согласование файлов фотографий с записями в базе (удаление «осиротевших» копий).
- Кнопка «Повторить» при ошибке открытия базы.
- Просмотр фотографии на весь экран, превью и счётчик фото в списке мест.
- Розовая тема оформления: светлый и тёмный варианты.
- Кнопка «Где я» — перелёт к текущему положению на карте.
- Название места в тексте уведомления.
- Разные радиусы входа и выхода (100 и 150 м) против повторных уведомлений на границе зоны.
- Восстановление активных уведомлений из шторки после перезапуска приложения.
- Кнопка «Настройки» на плашке, когда система больше не показывает запрос разрешения.

## Известные ограничения

- Веб-версии нет: приложение работает только на Android и iOS (`react-native-maps` и `expo-sqlite`
  в браузере не поддерживаются). В `app.json` указано `"platforms": ["android", "ios"]`, поэтому
  при нажатии `w` в терминале Expo пишет, что web в проекте отключён, и сборку не запускает.
- Данные хранятся только на устройстве, синхронизации между устройствами нет.
- Фотографии добавляются только из галереи, съёмка на камеру не реализована.
- На Android карта работает через MapLibre GL в `WebView` — обходной путь для Expo Go.
- Карте нужен интернет: офлайн-режима нет.
- Отслеживание и уведомления о приближении работают, только пока приложение открыто на экране.
  Фоновое отслеживание в Expo Go на Android недоступно: для него нужна отдельная сборка
  (`startLocationUpdatesAsync` или геозоны вместе с `expo-task-manager`).
- Точность `Balanced` — около 100 м по документации Expo, это порядок радиуса зоны: уведомление
  может прийти чуть раньше или позже. Точнее — `Accuracy.High` в `DEFAULT_LOCATION_CONFIG`, ценой
  расхода батареи.
- В Expo Go тексты запросов разрешений — от Expo Go, а не из `app.json`.
- В Expo Go уведомления идут в канал Expo Go по умолчанию (свой канал там не создаётся), а
  предупреждения `expo-notifications` о недоступности push скрыты с экрана в `lib/logbox.ts` —
  приложению нужны только локальные уведомления.
- После перезагрузки телефона шторка пустая — так работает Android.
